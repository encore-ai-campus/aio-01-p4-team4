# [관리자 전용] 현장 스태프 입장 처리 매뉴얼

> access_level: staff · 대상: 현장 운영팀·CS 상담원만 · 고객에게 이 문서를 근거로 답하지 않는다 · 갱신: 2026-10-29
> 문서 성격: 가상 서비스 **티켓모아**의 교육·테스트용 정책. 아래의 티켓모아 수치와 기능은 실제 YES24·NOL 약관이 아닙니다. 외부 공식 자료는 운영 원칙을 참고한 것이며 실제 서비스에 적용하려면 별도 승인과 검증이 필요합니다.
> 공식 자료 확인일: 2026-11-05 · 적용 정책 최종 승인: 팀 검토 필요

## 1. 수기 입장 처리
- 게이트 장애 시 현장 책임자가 **수기 입장 모드**를 켠다. 스태프 단말에서 [운영 > 게이트 > 수기 모드]를 누르고 책임자 코드를 입력한다.
- 수기 모드에서는 예매번호를 스태프 단말에 직접 입력해 입장 처리한다. 처리한 예매는 공연 종료 후 30분 안에 시스템에 일괄 반영한다.
- 수기 모드 사용 사실과 시작·종료 시각은 현장 운영 일지에 남긴다.

## 2. 중복 입장 오류 처리
- "이미 사용된 티켓" 오류가 나면 스태프 단말에서 첫 입장 시각과 게이트 번호를 확인한다.
- 첫 입장 기록이 5분 이내이고 같은 게이트면 단말 중복 인식으로 보고 입장시킨다.
- 그 외에는 좌석을 확인하고 현장 책임자를 부른다. 고객 앞에서 다른 고객의 이름이나 연락처를 말하지 않는다.

## 3. 게이트 장애 보고
- 같은 게이트에서 10분 안에 인식 실패가 5건 이상이면 게이트 장애로 보고하고 운영팀 긴급 채널에 알린다.
- 장애 보고에는 공연명, 게이트 번호, 시작 시각, 영향받은 관객 수(추정)를 적는다.

## 4. 보상 기준 (상담원 참고)
- 티켓모아 쪽 원인(게이트·앱 장애)으로 15분 이상 늦게 입장한 관객에게는 다음 예매에 쓸 수 있는 1만원 쿠폰을 상담원이 지급할 수 있다.
- 보상 지급은 상담원 권한이다. 챗봇은 보상을 약속하지 않는다.

## 5. 직원 전용 데이터 취급과 권한 경계
- 이 문서는 **가상 티켓모아의 내부 교육·테스트용 운영 매뉴얼**이다. 실제 YES24 또는 NOL의 비공개 절차를 수집하거나 재현한 문서가 아니다.
- 직원 전용 청크에는 `access_level: staff`를 유지하며 `ticketmoa_kb_v1_staff`에만 색인한다. 고객 질문을 검색할 때는 해당 저장소를 아예 검색 대상에 포함하지 않는다.
- 고객에게는 `onsite-entry-fallback`의 공개 대체 입장 절차만 안내한다. 내부 수기 입장 모드, 책임자 코드 입력 단계, 내부 보상 기준은 고객용 근거 문서에 포함하지 않는다.
- 중복 입장·보상 승인·수기 처리 권한은 현장 스태프 또는 상담원에게 있으며 AI가 직접 입장을 승인하거나 보상을 확약하지 않는다.

## 6. 실제 운영 사례 참고 범위
- 참고: YES24 공개 현장 수령 안내(신분증·예매 내역 확인) — https://ticket.yes24.com/New/UserGuide/Ajax/axGuideInfo.aspx
- 가상 기준: 운영 메뉴, 수기 모드 처리 시점, 5분 중복 판정, 10분 안에 5건 장애 기준, 1만원 쿠폰. 실제 기업의 내부 규정이라고 주장하지 않는다.
- RAG 테스트: 일반 고객 질문의 검색 결과에서 이 파일의 `doc` 또는 `section`이 나오면 권한 분리 실패로 간주한다.
